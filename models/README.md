# Models

Trained weights and the registry the backend serves. Nothing here is code.

```
models/
  cae/        the 16 per-unit convolutional autoencoders served by the app
    <machine>_<id>/model.keras, norm.npz   weights and scaling constants (gitignored, 16 MB each)
    registry.json, samples.json            generated by backend/scripts/build_registry.py (committed)
  local/      the extra model made by backend/train.py (fan id_02, local recordings)
    model.keras                            weights (gitignored)
    eval.json, norm.json                   metrics and scaling constants (committed)
  archive/    original zip files (gitignored)
```

## The 16 served models

One autoencoder per machine unit (4 machines x IDs 00, 02, 04, 06), trained on healthy 6 dB recordings only. Each takes a 128 x 64 log-Mel picture, has 1,315,297 parameters and scales its input with the min-max range stored in `norm.npz` (taken from the training set only).

They are the output of `notebooks/kaggle_2_conv_autoencoder_CAE.ipynb`, which saves each run to `/kaggle/working/outputs_cae/<machine>_<id>/`. To get them:

1. Run notebook 2 on Kaggle (or use your copy of its output).
2. Download `outputs_cae/` and unzip it into `models/cae/`, so that `models/cae/fan_id_00/model.keras` exists.
3. Rebuild the registry from the exported results:

```bash
python backend/scripts/build_registry.py --exports results
```

The registry holds the thresholds, ROC curves, score distributions, confusion matrices and loss curves, all taken from the notebook's CSV results, so nothing is retrained.

**Split caveat.** The CAE run used a random split of the healthy clips, which is not the strictest test. See the model comparison in the main README.

## The local model

`PYTHONPATH=backend python backend/train.py --data fan/id_02` trains one model on local fan clips and writes it to `models/local/`. The local clips are probably -6 dB, so this model is not comparable with the 6 dB models above.
